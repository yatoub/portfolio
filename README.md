# yatoub.dev

Portfolio of Yatoub, systems administrator / DevOps, and a set of small pages that
show how the network works by doing it on the visitor's own connection.

The site is static: HTML, CSS and vanilla JavaScript, no framework, no bundler, no npm dependency.
It is served by a self-hosted Caddy on a homelab.

## Pages

Beyond the home page, each standalone page is named after a Linux command and does what the command
does, on the site itself or on your connection: `whoami`, `tcpdump`, `traceroute`, `ping`, `dig`,
`curl`, `ipcalc`, `nc`, `xxd`, `nft`, `tail`, `status`. The full list, with one line each, is the
manual page of the site: <https://yatoub.dev/man/>.

The home page also embeds a terminal (the `>_` button or Ctrl+K), and `curl https://yatoub.dev`
returns a plain-text resume.

## Repository layout

| Path | What it holds |
|---|---|
| `index.html`, `styles.css`, `script.js`, `translations.js` | The home page, in English and French |
| `<command>/` | One directory per standalone page: `index.html`, `styles.css`, `translations.js`, a `script.js` for the DOM and a pure, tested `core.js` |
| `assets/` | Fonts, images, the helper and base styles shared by standalone pages, and vendored libraries (`assets/vendor/`) |
| `term/` | The terminal overlay of the home page |
| `lab/` | The homelab page, served behind authentication |
| `projects.json`, `lab/services.json` | The data behind the project and homelab cards |
| `tools/` | The build script, its templates and the tests |

Some files are generated by the build and committed, because the server only pulls the repository:
`curl.txt`, `homelab.json`, `sitemap.xml`, and the pre-rendered parts of `index.html` and
`man/index.html` (cards, lists and every translated string). Edit their sources, then rebuild.

## Working on it

Node 22 or later is the only requirement.

```bash
python3 -m http.server 8000      # serve the site on http://localhost:8000
node tools/build.mjs             # regenerate the derived files and the pre-rendered HTML
node tools/build.mjs --check     # fail if they are stale
node --test tools/*.test.mjs     # run the tests
```

Run the build after changing `projects.json`, `lab/services.json`, a `translations.js` used by a
pre-rendered page, or `tools/curl.tpl.txt`.

A few things only work behind the real server: the pages that show what the server sees of a
connection rely on Caddy templates, and the status and traffic pages read data files written on
the server.

## Deployment

A push to `main` runs the CI (`.github/workflows/deploy.yml`): syntax check of every script, the
tests, and `node tools/build.mjs --check`. If it passes, a signed webhook tells the server to
`git pull`. A failed check deploys nothing.
